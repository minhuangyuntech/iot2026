本頁整理嵌入式系統與 IoT 裝置最常見的三種通訊介面：I2C、SPI、UART。內容包含基本原理、接線方式、時序觀念、常見除錯方法，以及 Python / MicroPython 範例與常用模組。

一、為什麼要學通訊介面

150|
    151|
  • 感測器、螢幕、記憶體、GPS、藍牙模組都需要與主控板交換資料。
    • 152|
  • 不同模組不一定使用同一種通訊方式。
    • 153|
  • 選對介面可以降低接線難度、提升速度，並減少除錯時間。
    • 154|
  • 理解介面後，便能從 datasheet、接線圖與時序圖判斷模組的通訊需求。
    • 155|

二、先記住的總結

160|
    161|
  • I2C：兩條線、可掛多裝置，常用於多感測器與低速周邊。
    • 162|
  • SPI：速度快、全雙工、常用於顯示器與高速周邊。
    • 163|
  • UART：最直觀、最像序列埠，常用於除錯、GNSS、藍牙與數據機模組連接。
    • 164|
165|
建議的學習順序可先從 UART 開始，再進入 I2C，最後學習 SPI，以便循序掌握序列通訊、位址機制與時序控制。

四、I2C 介面

194|

1. 基本觀念

195|
    196|
  • SDA：資料線
    • 197|
  • SCL：時脈線
    • 198|
  • 每個裝置都有位址，常見為 7-bit 位址。
    • 199|
  • 多個裝置可以掛在同一組 SDA / SCL 上。
    • 200|
201| 202|

2. I2C 為什麼常用於感測器

203|
    204|
  • 接線少
    • 205|
  • 可讓一台主控板同時連接多個環境感測器
    • 206|
  • 許多常見模組都提供 I2C 介面與現成函式庫
    • 207|
208| 209|

3. 常見問題

210|
    211|
  • 忘了接上拉電阻（pull-up resistor）
    • 212|
  • 位址衝突：兩個裝置位址相同
    • 213|
  • 電壓不相容：3.3V 裝置與 5V 裝置直接混接
    • 214|
  • 線太長、干擾太大導致通訊不穩
    • 215|
216| 217|

4. 重要術語

218| 219| 220| 221| 222| 223| 224| 225| 226| 227| 228| 229|
術語說明
Start Condition主機開始一筆 I2C 傳輸的訊號。
Stop Condition主機結束一筆 I2C 傳輸的訊號。
ACK / NACK接收端是否確認收到資料。
7-bit address最常見的裝置位址格式。
Pull-up resistorSDA、SCL 常需要上拉到高電位。

五、SPI 介面

253|

1. 基本觀念

254|
    255|
  • MOSI：Master Out, Slave In
    • 256|
  • MISO：Master In, Slave Out
    • 257|
  • SCLK：時脈
    • 258|
  • CS / SS：晶片選擇
    • 259|
260| 261|

2. SPI 的特點

262|
    263|
  • 速度通常比 I2C 快
    • 264|
  • 常見於顯示器、外部 Flash、高速 ADC
    • 265|
  • 每個從屬裝置通常需要一條獨立的 CS 線
    • 266|
267| 268|

3. 為什麼 SPI 比較快

269|
    270|
  • 沒有 I2C 的位址仲裁與 ACK/NACK 流程負擔
    • 271|
  • 可全雙工傳輸
    • 272|
  • 時序結構相對直接
    • 273|
274| 275|

4. 實作時要特別注意

276|
    277|
  • SPI 沒有統一的「位址掃描」概念
    • 278|
  • 不同裝置的 CPOL、CPHA 可能不同
    • 279|
  • CS 拉低與拉高的時機很重要
    • 280|
281| 282|

5. SPI Mode 概念

283| 284| 285| 286| 287| 288| 289| 290| 291| 292| 293|
ModeCPOLCPHA說明
Mode 000最常見，時脈閒置低，前緣取樣
Mode 101時脈閒置低，後緣取樣
Mode 210時脈閒置高，前緣取樣
Mode 311時脈閒置高，後緣取樣

6. MicroPython 範例

296| 
from machine import Pin, SPI
   297|
   298|spi = SPI(0, baudrate=1000000, polarity=0, phase=0,
   299|          sck=Pin(18), mosi=Pin(19), miso=Pin(16))
   300|cs = Pin(17, Pin.OUT)
   301|
   302|cs.value(0)
   303|spi.write(b'\x9F')
   304|chip_id = spi.read(3)
   305|cs.value(1)
   306|
   307|print(chip_id)
308| 309|
SPI 裝置最常見的錯誤不是「完全沒接好」，而是 mode 設錯、CS 切換時機不對、或 baudrate 太高。

314|

1. 基本觀念

315|
    316|

  • RX：接收線
    • 318|

八、接線觀念與電壓注意事項

447|
    448|
  • 先確認裝置工作電壓：3.3V 或 5V。
    • 449|
  • Raspberry Pi 與 Pico W 大多是 3.3V 邏輯，不可直接承受 5V GPIO。
    • 450|
  • 共地（GND）通常是通訊成功的前提。
    • 451|
  • UART 錯接最常見是 TX/RX 沒交叉；I2C 錯接最常見是 SDA/SCL 對調；SPI 錯接最常見是 CS 沒接或接錯。
    • 452|
453|
裝置成功供電不代表通訊一定成功；電壓、共地、腳位與協定參數都必須同時正確。

九、如何選擇 I2C、SPI、UART

458| 459| 460| 461| 462| 463| 464| 465| 466| 467| 468|
情境建議介面原因
多個低速感測器I2C接線省、可共用匯流排
高速顯示器或外部記憶體SPI速度高、時序直接
模組除錯與字串傳輸UART容易理解、終端機可直接觀察
兩塊板子先做簡單通訊實驗UART最容易做出第一個成功結果

十、常見除錯方法

473|

1. I2C 除錯

474|
    475|
  • 先掃描位址，看裝置有沒有被偵測到
    • 476|
  • 檢查 pull-up 電阻是否存在
    • 477|
  • 降低頻率，例如從 400kHz 改成 100kHz
    • 478|
479| 480|

2. SPI 除錯

481|
    482|
  • 確認 datasheet 的 SPI mode
    • 483|
  • 先把 baudrate 降低
    • 484|
  • 檢查 CS 的拉低/拉高時序
    • 485|
486| 487|

3. UART 除錯

488|
    489|
  • 確認 baud rate 一致
    • 490|
  • 確認 TX/RX 有交叉接
    • 491|
  • 確認雙方都共地
    • 492|
493| 494|
