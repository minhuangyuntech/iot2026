常見介面 I2C, SPI, UART 教材

本頁整理嵌入式系統與 IoT 裝置最常見的三種通訊介面：I2C、SPI、UART。除了基本原理與接線方式，也補充時序觀念、常見除錯方式、Python / MicroPython 範例與教學實驗建議。

I2C SPI UART Raspberry Pi Pico W ESP32

一、為什麼要學通訊介面

  • 感測器、螢幕、記憶體、GPS、藍牙模組都需要與主控板交換資料。
  • 不同模組不一定使用同一種通訊方式。
  • 選對介面可以降低接線難度、提升速度，並減少除錯時間。
  • 理解介面後，學生才不會只會「照抄範例」，而能真正看懂 datasheet。

二、先記住的總結

  • I2C：兩條線、可掛多裝置、最適合多感測器教學。
  • SPI：速度快、全雙工、常用於顯示器與高速周邊。
  • UART：最直觀、最像序列埠、最適合除錯與模組連接。
如果是入門課：先教 UART，再教 I2C，最後教 SPI，學生通常比較容易建立概念。

三、三種介面的整體比較

項目 I2C SPI UART
線數2 條主線（SDA, SCL）至少 4 條（MOSI, MISO, SCLK, CS）2 條主線（TX, RX）
拓樸多主/多從匯流排單主多從較常見點對點
位址機制有裝置位址通常靠 CS 選擇裝置無位址概念
速度低到中高中
全雙工否是通常可雙向，但不如 SPI 典型
適合裝置感測器、RTC、EEPROMTFT、ADC、Flash、RF 模組GPS、藍牙、序列除錯
教學難度中中偏高低

四、I2C 介面

1. 基本觀念

  • SDA：資料線
  • SCL：時脈線
  • 每個裝置都有位址，常見為 7-bit 位址。
  • 多個裝置可以掛在同一組 SDA / SCL 上。

2. I2C 為什麼適合感測器

  • 接線少
  • 很適合一台主控板連多個環境感測器
  • 很多教學模組都已內建 I2C 支援

3. 常見問題

  • 忘了接上拉電阻（pull-up resistor）
  • 位址衝突：兩個裝置位址相同
  • 電壓不相容：3.3V 裝置與 5V 裝置直接混接
  • 線太長、干擾太大導致通訊不穩

4. 重要術語

術語說明
Start Condition主機開始一筆 I2C 傳輸的訊號。
Stop Condition主機結束一筆 I2C 傳輸的訊號。
ACK / NACK接收端是否確認收到資料。
7-bit address最常見的裝置位址格式。
Pull-up resistorSDA、SCL 常需要上拉到高電位。

5. Raspberry Pi Python 範例概念

from smbus2 import SMBus

I2C_BUS = 1
DEVICE_ADDR = 0x48
REGISTER = 0x00

with SMBus(I2C_BUS) as bus:
    data = bus.read_byte_data(DEVICE_ADDR, REGISTER)
    print("read:", data)

6. Pico W MicroPython 掃描 I2C 位址

from machine import Pin, I2C

i2c = I2C(0, scl=Pin(1), sda=Pin(0), freq=400000)
print('devices:', [hex(x) for x in i2c.scan()])
教學上很適合先用 i2c.scan() 讓學生看到裝置位址，再進入寄存器讀寫。

五、SPI 介面

1. 基本觀念

  • MOSI：Master Out, Slave In
  • MISO：Master In, Slave Out
  • SCLK：時脈
  • CS / SS：晶片選擇

2. SPI 的特點

  • 速度通常比 I2C 快
  • 常見於顯示器、外部 Flash、高速 ADC
  • 每個從屬裝置通常需要一條獨立的 CS 線

3. 為什麼 SPI 比較快

  • 沒有 I2C 的位址仲裁與 ACK/NACK 流程負擔
  • 可全雙工傳輸
  • 時序結構相對直接

4. 教學上要特別提醒

  • SPI 沒有統一的「位址掃描」概念
  • 不同裝置的 CPOL、CPHA 可能不同
  • CS 拉低與拉高的時機很重要

5. SPI Mode 概念

ModeCPOLCPHA說明
Mode 000最常見，時脈閒置低，前緣取樣
Mode 101時脈閒置低，後緣取樣
Mode 210時脈閒置高，前緣取樣
Mode 311時脈閒置高，後緣取樣

6. MicroPython 範例

from machine import Pin, SPI

spi = SPI(0, baudrate=1000000, polarity=0, phase=0,
          sck=Pin(18), mosi=Pin(19), miso=Pin(16))
cs = Pin(17, Pin.OUT)

cs.value(0)
spi.write(b'\x9F')
chip_id = spi.read(3)
cs.value(1)

print(chip_id)
SPI 裝置最常見的錯誤不是「完全沒接好」，而是 mode 設錯、CS 切換時機不對、或 baudrate 太高。

六、UART 介面

1. 基本觀念

  • TX：傳送線
  • RX：接收線
  • 接線規則通常是 TX → RX、RX → TX
  • 雙方要設定相同 baud rate

2. UART 最常見的參數

參數常見值說明
Baud rate9600, 115200每秒傳輸符號速率
Data bits8資料位元數
ParityNone / Even / Odd同位檢查
Stop bits1 或 2結束位元

3. UART 適合哪些場景

  • 連接 GPS 模組
  • 連接藍牙模組
  • 序列除錯輸出
  • 兩塊板子之間傳送簡單字串或封包

4. MicroPython 範例

from machine import UART, Pin
import time

uart = UART(0, baudrate=115200, tx=Pin(0), rx=Pin(1))

while True:
    uart.write('hello from pico\n')
    if uart.any():
        msg = uart.read()
        print(msg)
    time.sleep(1)

5. Raspberry Pi Python 範例

import serial

ser = serial.Serial('/dev/serial0', 115200, timeout=1)
ser.write(b'hello from pi\n')
print(ser.readline().decode(errors='ignore'))
在課堂上，UART 很適合拿來做「Pico W 傳資料給 Raspberry Pi」，因為學生可以直接看見字串與回應。

七、接線觀念與電壓注意事項

  • 先確認裝置工作電壓：3.3V 或 5V。
  • Raspberry Pi 與 Pico W 大多是 3.3V 邏輯，不可直接承受 5V GPIO。
  • 共地（GND）通常是通訊成功的前提。
  • UART 錯接最常見是 TX/RX 沒交叉；I2C 錯接最常見是 SDA/SCL 對調；SPI 錯接最常見是 CS 沒接或接錯。
很多學生會把「供電成功」誤以為「通訊就一定成功」；實際上電壓正確、共地正確、腳位正確、協定參數正確，四者缺一不可。

八、如何選擇 I2C、SPI、UART

情境建議介面原因
多個低速感測器I2C接線省、可共用匯流排
高速顯示器或外部記憶體SPI速度高、時序直接
模組除錯與字串傳輸UART容易理解、終端機可直接觀察
兩塊板子先做簡單通訊實驗UART最容易做出第一個成功結果

九、常見除錯方法

1. I2C 除錯

  • 先掃描位址，看裝置有沒有被偵測到
  • 檢查 pull-up 電阻是否存在
  • 降低頻率，例如從 400kHz 改成 100kHz

2. SPI 除錯

  • 確認 datasheet 的 SPI mode
  • 先把 baudrate 降低
  • 檢查 CS 的拉低/拉高時序

3. UART 除錯

  • 確認 baud rate 一致
  • 確認 TX/RX 有交叉接
  • 確認雙方都共地

4. 進階工具

  • 邏輯分析儀（logic analyzer）
  • 示波器
  • 序列埠監看工具
若課堂允許，加入 logic analyzer 的示範會非常有教學價值，因為學生能直接看見時序而不只是一段程式碼。

十、課堂實驗建議

  1. UART：Pico W 與 Raspberry Pi 互傳字串
  2. I2C：掃描感測器位址並讀取一個寄存器
  3. SPI：讀取 SPI Flash 或小型顯示器裝置 ID
  4. 綜合題：比較三種介面的接線、速度與除錯難度
很建議把這頁教材與後續 MQTT、DDS、Node-RED 教材串起來，讓學生知道：硬體資料是先透過 I2C/SPI/UART 進入板子，再往網路層與應用層送出去。

十一、與後續 IoT / DDS 教材的連結

  • I2C / SPI 常用來「讀取感測資料」
  • UART 常用來「板與板之間」或「除錯」
  • 之後可再把取得的資料送到 MQTT 或 DDS 系統
  • 例如：Pico W 用 I2C 讀溫濕度 → 用 Wi-Fi HTTP 傳給 Pi 5 → Pi 5 Bridge 發到 DDS

十二、常見問答

1. I2C 為什麼只用兩條線卻可以掛很多裝置？

因為它用位址區分裝置，所以多個從屬可共用 SDA / SCL。

2. SPI 為什麼速度通常比 I2C 快？

因為它的時序較直接，而且常見情況下不需要像 I2C 一樣處理位址與 ACK 流程。

3. UART 為什麼常被拿來做除錯？

因為它非常直觀，終端機就能看到輸出結果，對初學者很友善。

4. 初學者要先學哪一個？

建議先學 UART，再學 I2C，最後再進入 SPI。
